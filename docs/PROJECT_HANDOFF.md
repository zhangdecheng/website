# FLOURISH CULTURE Website Project Handoff

Last updated: 2026-06-25

## Project background

This repository contains the static English landing page for FLOURISH CULTURE at `flourishculturekol.com`.

The current production direction is the approved Option 1, “Neon Culture Bridge”: a black, coral-red, high-impact global creator growth site. The site replaced the earlier white/green Chinese draft, which is retained only as a rollback/reference snapshot under `archive/2026-06-19-white-green-draft/`.

The site must remain pure static HTML/CSS/JavaScript:

- no API
- no database
- no cookies
- no analytics/tracking
- no server-side form handler
- no additional pages for this phase

The production server also hosts the separate `/review/` TikTok review application. Homepage releases must not modify Nginx configuration, certificates, `/review/` application files, `/review/` data, or service configuration.

## Build and release commands

Local verification:

```bash
npm test
npm run build
cd dist && zip -qr ../release/flourishculturekol-homepage.zip .
```

Local preview:

```bash
npm run serve
```

Open `http://127.0.0.1:4173/`.

Production deployment, only after explicit approval:

```bash
bash deploy-cloud-assistant.sh /path/to/flourishculturekol-homepage.zip
```

The deploy script backs up the current web root, copies the static package into `/var/www/flourishculturekol.com`, restores web-readable file permissions, and validates Nginx syntax. It deliberately does not rewrite Nginx config and does not touch `/review/`.

Lessons from the release:

1. Do not judge a release by HTTP 200 alone; verify rendered page content and browser console.
2. Do not use `.mjs` browser module files unless Nginx is configured to serve `.mjs` as JavaScript. This project now uses `site-core.js`.
3. After copying static files from a temporary extraction directory, reset directory and file permissions so Nginx can read the web root.
4. Continue checking `/review/healthz` and `/review/` redirect behavior after homepage releases.
5. Before publishing, confirm DNS and server behavior identify the correct production host; the historical homepage target is `150.5.135.196`, not every similarly named ECS instance.
6. Keep the release archive minimal: do not copy the entire `assets/` tree when the homepage only needs optimized WebP photos, brand logos, fonts, and icon fonts.

## Recovery

If the homepage needs rollback:

1. SSH to the production server.
2. Identify the desired backup under `/var/backups/flourishculturekol.com/`.
3. Restore the backup to `/var/www/flourishculturekol.com`.
4. Reapply web-readable permissions if needed.
5. Run `nginx -t`.
6. Verify homepage, key assets, and `/review/healthz`.

Do not patch production files piecemeal unless the root cause is understood and the change is minimal.
