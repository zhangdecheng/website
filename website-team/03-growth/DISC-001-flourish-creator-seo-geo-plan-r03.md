## 一、STAR 汇报

### S｜Situation（背景与现状）

FLOURISH CULTURE 英文官网同时面向品牌与创作者。首页英文单页含服务、Why Creators Partner With Us、联系入口；创作者内容多为同页区块。公开首页首屏主标题仍偏品牌向（“Scaling Global Impact for Visionary Brands.”），与「达人申请」意图容易脱节。

业务已明确本阶段优先**达人获客/孵化向合作**：希望英文搜索「经机构接品牌合作 / 加入创作者网络」的人能发现并理解可申请。品牌路径次要。英站+英文意图。Search Console **可先人工查看/导出**，连接器安装**不是**开工前置条件。

### T｜Task（目标）

**问题**  
达人缺少一个可单独收录、可理解、可申请的英文合作入口；仅改搜索摘要而首屏仍纯品牌向，会导致「搜到的承诺」与「点进来看到的」不一致。

**本阶段目标（可验收，不保证幅度）**

1. **交付**：首页摘要调整 + **一个**独立英文创作者合作页一并上线，且进入真实发布产物并公网可读回。  
2. **看见（技术/初始信号）**：新页与首页可核验收录/抓取状态；Search Console 人工可读展示与点击（≠ 站点 PV）。  
3. **理解（诊断样本）**：固定英文问题样本上可观察提及/引用/推荐（分列记录）；未出现≠业务失败。  
4. **申请**：跨页进入表单且 Creator 预选正确；邮件「送达」可核对；另标签「有效申请」「目标匹配」（见下文），**不把邮件量当 SEO 及格线**，无来源证据不计为 SEO 获客。

**非目标**  
教程站；默认上 PDF 业绩数字；本阶段多页扩张；未授权改邮件路由；连接器未装就不允许人工看 GSC。

### A｜Action（当前业务动作｜确认 r03 并冻结后）

**一件事**：让目标达人更容易发现、理解并提交 Creator 申请。

1. **首页（不改整体版式）**  
   - 调整英文 title / description / 必要 JSON-LD。  
   - **必补**：首屏一句创作者合作说明 + 清晰 Creator 入口（可链到新页或预选 Creator 的联系区）。  
   - 首页保留公司整体定位；达人申请意图主要由新页承接。

2. **独立创作者页（默认 `/creators`，占用则 `/creator-partnership`，全案唯一）**  
   - 真实独立 URL，200，正文≠首页；禁止软回退首页。  
   - **价值主张基础**：Why Creators 四条同义表述。  
   - **允许补充**（须业务确认后再写进页）：申请条件、流程、FAQ（费用/独家/是否零基础等）；未知项不由文案臆造。  
   - CTA：明确 Creator 申请文案 → 现有 Contact 且 **`role=creator` 预选**；禁止泛 Contact Us。

3. **服务定位（对外用词｜待业务一句话确认后锁死）**  
   - **推荐默认（待确认）**：创作者合作网络 / 品牌撮合 + 商务运营支持 + 成长辅导（对应官网四条），**不是**默认「独家经纪签约管理」或「零基础网红培训班」。  
   - `incubator` / `management` / `agency` 等词仅在业务确认匹配时使用；页上须写清「实际提供什么、不提供什么」。

4. **目标达人边界（框架｜以下带「待确认」项须业务填完再冻结文案）**

| 维度 | 本版建议默认 | 状态 |
| --- | --- | --- |
| 语言/站 | 英文官网、英文意图 | 已确认 |
| 平台 | TikTok / Instagram / YouTube（与官网公开一致） | 建议，待确认是否收窄 |
| 地区 | 先服务官网能力可覆盖的跨境合作（香港连接叙事）；不在页上承诺「全球任意国家必接」 | 待确认优先国家列表 |
| 阶段 | 优先「已有或准备做社媒内容、想接品牌合作/找机构协助」的创作者 | 待确认 |
| 粉丝门槛 | **不得默认**；有/无门槛由业务书面确认后再写进页 | **待确认** |
| 明确不优先 | 只想看涨粉教程、无合作意向的访客 | 已确认方向 |

5. **申请条件与流程（页上可写的最小集｜细节待业务确认）**  
   - 流程示意：了解合作 → 提交 Creator 申请表 → 团队评估邮件 → 沟通合作方式。  
   - 页上须区分：普遍提供 vs 按项目提供（如工厂参访、垫付、某市场 TAP 相关能力）。  
   - 费用、独家、签约形式：**未确认前不写死承诺**。

6. **工程与发布**  
   - robots.txt（真实）、sitemap 含新页绝对 URL、自指 canonical、独立 title/H1、无意外 noindex、可抓取内链。  
   - 新页 + robots + sitemap **必须进入 build/发布产物**；源码、构建包、公网三者一致才算交付完成。

7. **数据**  
   - 优先人工 Search Console；连接器为加分项非前置。  
   - 新页无上线前基期：先记绝对数，再用**同长度周期**比较；同比仅在有历史时用。  
   - 尽量分品牌词/非品牌词、首页/创作者页、国家（若 GSC 可得）。

## 三、申请结果拆分（必改｜写入业务与数据口径）

| 层级 | 定义 | 用途 |
| --- | --- | --- |
| **申请送达** | Contact 以 Creator 提交且服务端成功并产生 Creator 路由邮件（主题含 New Creator Application 等既有逻辑） | 证明「表单链路通」；**201≠收件箱送达**，生产送达须受控实测 |
| **有效申请** | 送达 + 关键字段完整（如社媒/联系方式等业务规定的最低集） | 可跟进的申请 |
| **目标匹配申请** | 有效 + 人工/规则标签符合目标达人边界（平台/地区/意向等） | 判断获客质量 |
| **SEO 获客** | 目标匹配（或有效）且有可核验来源指向本站搜索/本页；否则标 **来源未知**，**不计 SEO 获客** | 禁止把「邮件变多」直接归因 SEO |

本阶段 SEO 交付及格线：**不绑定**邮件量；绑定的是页面与链路验收 + 数据可观察。

## 四、内容与事实边界

1. Why Creators 四条 = **价值主张基础**（全球品牌对接、商务合规结算、数据成长辅导、社群/供应链资源）。

3. 官网已写过 ≠ 事实已核实：付款时效、独家、线下活动、工厂参访、TAP/CAP 等须在事实表注明负责人、适用市场/对象、普遍 vs 按项目。  
4. PDF 业绩数字默认不上公开摘要/标题；批准后方可带来源上页。  
5. 首页摘要与新页 H1/首段用词一致；CTA 必须是 Creator 申请语义。

## 五、技术与发布验收必选（在 r02 基础上补齐）

1. 路径唯一：`/creators`（或确认后的等价路径）。  
2. GET 200；正文可区分；禁止回退首页。  
3. 独立 title、H1；**自指 canonical**；无意外 **noindex**；可抓取内链。  
4. 真实 robots.txt + sitemap 含绝对 URL。  
5. **跨页申请链**：创作者页 CTA → 表单页 → **Creator 已预选** → 正确字段 → 按原流程提交（发送实测另授权）。  
6. **发布产物**：新页、robots、sitemap 进入 build/发布清单；源码 / 构建包 / 公网一致。  
7. 不改邮件路由；不强制多语言。
